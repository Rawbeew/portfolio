flippy

AI / LLM applications

A multi-provider inference router (zero non-stdlib deps) plus a unified AI hub — chat, RAG, tool-calling, vision, TTS, STT — built on a free-first, auto-failover backbone across 4 providers.

Why it exists: every provider rate-limits you. The question is whether your system keeps working. This toolkit is the answer I built after a real production incident, and the code I'd want a candidate to show me if I were hiring.
Python multi-provider failover litellm RAG tool-calling vision TTS / STT

You-are-fired

Cold-outreach engineering

The portfolio version of a working cold-outreach system that finds a measurable defect, prices the fix, and drafts the email — by hand, one at a time, with evidence the prospect can check in 20 seconds. Capped sends, adversarial- tested safety, opt-out integrity.

Why it exists: cold outreach fails when it claims too much and proves too little. The single sentence that earns a reply is the one a prospect can verify themselves in twenty seconds. This system enforces that at every step.
gmail SMTP DNS adversarial-testing send-cap opt-out integrity

just-hired

Personal product — fresh-only job board

A working product: a static job board that shows only direct- employer postings released in the last 12 hours, refreshed every 2 hours by a Cloudflare Worker that bypasses Job Bank's datacenter-IP block. Built for a real person in a 30-day job search.

Why it exists: job boards show stale leads; the person searching wastes time on roles that were filled yesterday. This one only shows what's actually open right now, with commute-from-North-York badges and a tailored resume + cover letter per posting.
static site Cloudflare Worker Job Bank UHN Netlify ATS scoring

dont-get-rekt

LLM-as-decision engineering

The portfolio version of a paper-mode crypto signal engine: multi-chain data ingestion + a free-tier LLM casting the final structured BUY: / SKIP: vote per token. The model is the judge, not the source of truth — every gate the LLM cites is a value the pipeline already computed.

Why it exists: an LLM that trades real money on its own vote is a system with a single point of failure. An LLM that votes in a paper-mode engine with an adversarial-tested parser and an engine-side override is a system where the model is one component among several — and the only kind worth shipping.
crypto multi-chain paper-trading structured prompting free-tier LLM decisions, not vibes

How to read theseIf you're hiring, here is the order

Each repo has its own README, LLM.txt, and 4–5 engineering-decision posts. The pattern is always the same: what it is, what problem it solves, why it's built this way, what it's not. Reading them in order tells the same story four different ways.

  1. flippy — the AI/LLM infrastructure layer that the other three ride on.
  2. dont-get-rekt — what "LLM as one component, with adversarial-tested backstops" looks like in a high-stakes domain.
  3. You-are-fired — what "evidence-pinned, opt-out safe, send-cap disciplined" looks like in a real-world domain.
  4. just-hired — what "free-first infrastructure, refreshes itself, never serves stale data" looks like as a product.
